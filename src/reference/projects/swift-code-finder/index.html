01 / THE PROBLEM

A small code can create a lot of uncertainty.

People preparing an international transfer need to find the right bank identifier or check one they already have. Searching across websites leaves them comparing unfamiliar details without a consistent way to establish which result fits their task.

Starting point

  1. Search across several websites
  2. Compare unfamiliar bank and branch details
  3. Copy a code without a consistent checking step

Design direction

  1. Choose a country, bank and branch
  2. Review the matching bank details
  3. Use a separate path to check an existing code
  4. Copy the result with clear feedback

02 / RESEARCH & DISCOVERY

The needs behind the interface.

Finding a code

A guided search that narrows the options without requiring prior knowledge.

Checking a code

A direct way to inspect a code the user already has.

Understanding the result

Enough context to connect the result with the intended bank.

The project explored how people find SWIFT codes, what frustrates them and how they understand the parts of a code. Trust, speed and support for checking details shaped the design priorities.

03 / THE DESIGN REASONING

Four decisions that shape the experience.

  1. 01

    Guide the search in steps

    Country, bank and branch provide a clear sequence for finding a code.

  2. 02

    Give known codes a separate path

    Validation supports people who already have a code and need to check it.

  3. 03

    Explain without interrupting

    Short explanations sit alongside results so the main task remains finding and using the code.

  4. 04

    Make the result usable

    A one-tap copy action belongs beside the code. Clear feedback helps users understand whether the copy action succeeded, while the bank details remain available for review.

05 / FROM DESIGN TO EVIDENCE

The next iteration to validate.

The current material explains the approach, but does not document a complete tested iteration. This is a proposed test plan, not a claim that these sessions already happened.

Question

Can people distinguish between finding a code and checking a code they already have?

Proposed revision

Make the two entry points explicit and keep identifying bank details alongside the result.

What to observe

Give participants one search task and one checking task. Record the first path chosen, whether they check the bank details, and where they hesitate.

06 / OUTCOMES & MEASUREMENT

What to measure next.

Measure successful identification of the intended bank, time to reach a usable result, incorrect selections and understanding of the checking outcome. Record task definitions and sample sizes before comparing designs.
