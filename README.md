# Ajaymon portfolio

A local static portfolio using a shared Paperline-style design system: charcoal canvas, cutting-mat compositions, outlined sticker headings, yellow controls and illustrated storytelling.

## Run

```sh
npm run dev
```

Open http://127.0.0.1:5173. Node.js 22.12+ is required.

```sh
npm run check
npm run build
npm run preview
```

Build produces `dist/`. Stop the development server before previewing on the same port, or use `PORT=5174 npm run preview`.

## Design and content

[DESIGN.md](DESIGN.md) documents the tokens, typography, page compositions, interactions and responsive rules. Shared tokens live in `public/reference/profile/design-tokens.css`; `home.css` and `pages.css` implement them.

Edit `src/profile/profile.json` for profile and case study content, then regenerate:

```sh
python3 scripts/home-page.py
python3 scripts/about-page.py
python3 scripts/portfolio-pages.py
npm run build
```

The generators require only Python’s standard library. `scripts/portfolio_layout.py` owns the shared navigation, footer, metadata and modal frame. The About generator contains its three short illustrated chapter captions. Supplied photographs, résumé and project imagery live in `public/reference/profile/`.

## Pages

- `/`: compact fintech introduction, readable process note, contribution-led project cards and detail gallery.
- `/about`: illustrated data → people → product story and résumé link.
- `/projects`: filterable project index.
- `/projects/karbon-forex`, `/projects/taxos`, `/projects/swift-code-finder`, `/projects/karbon-design-system`, `/projects/karbon-business`: case studies with image enlargement and next-project navigation.
- `/contact`: contact details and an email-draft form. Visitors review and send in their email app; no backend stores or sends submissions.
- `/404`: matching not-found page, also served with HTTP 404 for unknown routes.

All active pages use the authored shared design system. `home.js` handles shared motion, image dialogs, email copying and homepage-only collage/audio controls. `pages.js` handles work filters and the contact draft. Motion respects reduced-motion preferences.

## Archived implementation

The original Visualfolio capture and motion assets remain in `public/reference/assets/` and `scripts/profile-baseline/`. Current pages do not load that runtime. `profile.css`, `enhancements.js`, `local.js` and `about.css` are legacy assets retained for the archival workflow. The earlier React starter remains available via `npm run dev:starter`; it is not the active portfolio.

`scripts/personalize.py` still refreshes archived content and then regenerates all authored pages. It uses the optional Python environment described by `requirements-profile.txt`. Do not run `mirror-reference.py` or `prepare-local.py` for normal edits; they overwrite captured files.

The site has not been published. Validation is code-only unless browser checks are requested.

Case studies currently include clearly labelled illustrative result figures, as requested for the draft. Replace those sections with verified project evidence before publishing. Project problem, contribution, output and decision content lives in `src/profile/profile.json`.

The focused invoicing case study keeps the `/projects/karbon-forex` route. Its narrative is generated by `scripts/invoice_case.py`, including the explicitly labelled preview exploration and measurement notes. Unlike the other draft case studies, it retains prior reported figures only inside an evidence disclosure rather than showing dummy metrics as its outcome snapshot. The original Framer-hosted page is not modified by these local generators.

The other three case studies use `scripts/project_story.py` and the `story` fields in `src/profile/profile.json`. They share the invoice case's chapter structure while retaining project-specific needs, decisions, screenshots and proposed measurement plans. Regenerate them with `python3 scripts/portfolio-pages.py`.

TaxOS is generated by `scripts/taxos_case.py`, adapted from the original case-study-2 with its own locally stored screenshots. Reported outcomes include visible measurement-context notes. Stable `image_index` values keep existing project assets independent of display order.
